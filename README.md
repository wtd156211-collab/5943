# 清洗引擎（内部批量文本清洗正则引擎）

内部批量文本清洗工具用的正则引擎，纯标准库实现（实现代码不依赖 `re`，
`re` 只在测试里用于对拍）。针对之前的事故做了三件事：

1. **不挂死**：匹配全程统计步数，超预算立即中止并说明是哪条规则、在哪段文本上超的；
   中止后引擎不留脏状态，同一进程可以连续跑几十万条。
2. **能定位**：模式写错时报出第几个字符、什么毛病（错误码 + 字符位置）。
3. **可验证**：`tests/` 里有带种子的随机对拍，随机生成模式和文本，
   匹配区间与捕获结果与标准库 `re` 逐一比对。

## 用法

```python
import cleanre

p = cleanre.compile(r"订单 (OD\d+) 客户 (\S+)")   # 编译一次，反复用
m = p.search("订单 OD5341017381 客户 陈涛")
m.span()        # (0, 22)
m.group(1)      # 'OD5341017381'
m.groups()      # ('OD5341017381', '陈涛')

p.findall(text)     # 所有不重叠匹配（行为对齐 re.findall）
p.finditer(text)    # 逐个产生 Match
p.match(text, pos)  # 只从 pos 位置开始尝试
```

编译时可以调整预算：`cleanre.compile(pattern, max_steps=500_000)`。

## 支持的语法

只支持 `samples/patterns.txt` 清单里的语法，清单外的一律不做：

| 语法 | 写法 | 说明 |
| --- | --- | --- |
| 字面量 | `abc` | 普通字符逐个匹配 |
| 点号 | `.` | 匹配除换行外的任意单个字符 |
| 字符类 | `[abc]` `[^abc]` `[a-z]` | 枚举、取反、区间 |
| 转义字符类 | `\d \D \w \W \s \S` | 数字、单词字符、空白及各自取反（Unicode 语义，与 `re` 一致） |
| 量词 | `*` `+` `?` `{n}` `{n,}` `{n,m}` | 重复次数，含区间写法 |
| 惰性量词 | `*?` `+?` `??` `{n,m}?` | 尽量少地匹配 |
| 分组 | `(...)` | 捕获组，编号按左括号顺序，`group(i)`/`span(i)` 可取 |
| 分支 | `a|b|c` | 任意一个分支匹配即算 |
| 锚点 | `^` `$` | 行首与行尾（多行语义：`\n` 之后/之前也算，对齐 `re.MULTILINE`） |

补充说明（与标准库行为对齐的边界）：

- 标点符号可以用反斜杠转义为字面量，如 `\.` `\[` `\\`。
- `\d \D \w \W \s \S` 之外的字母/数字转义（如 `\n` `\q`）不支持，报错误码 1006。
- `{` 不能构成合法量词时按字面量处理（如 `a{`、`a{x}`）。
- 字符类里 `]` 出现在第一个位置时按字面量处理；`-` 在首尾按字面量处理。
- 空匹配后的扫描行为对齐 Python 3.7+ 的 `re.finditer`
  （空匹配之后允许同一位置的非空匹配）。

## 步数预算怎么算

- 引擎是带回溯的虚拟机，**每执行一条虚拟机指令计 1 步**
  （字符比较、分支、跳转、捕获写入、锚点断言、循环守卫各算一条）。
- 预算按**“从某个起始位置的一次匹配尝试”**计算：`search`/`finditer`
  在文本上逐个位置尝试，每个位置都有独立的一份预算；`match` 只有起始位置一次尝试。
- 默认预算 `cleanre.DEFAULT_MAX_STEPS = 1_000_000` 步，
  可用 `cleanre.compile(pattern, max_steps=...)` 调整。
- 任意一次尝试超预算，立即抛出 `BudgetExceeded`（错误码 2001），整个查询中止。
  异常信息里带：规则原文、文本长度、超预算的起始位置、预算大小、附近文本摘录。
- 匹配所需全部状态都是单次调用的局部变量，**中止后不留任何脏状态**，
  同一个 `Pattern` 对象可以立刻继续用（`tests/test_budget.py` 里有
  中止后连续复用的回归测试）。
- 参考耗时：默认预算下一次失控尝试大约在 0.1 秒量级中止；
  `samples/corpus.txt`（约 30 万字符）上常见模式全量 `findall` 在 0.5 秒内。

## 错误码

### 解析错误（`PatternError`，含 `code` 和 `pos` 属性，`pos` 为 0 起始的字符下标）

| 错误码 | 含义 | 例子 |
| --- | --- | --- |
| 1001 | 左括号未闭合 | `(abc` |
| 1002 | 字符类未闭合（缺 `]`） | `ab[cd` |
| 1003 | 量词区间下限大于上限 | `a{3,2}` |
| 1004 | 字符类区间写反（起点大于终点） | `[z-a]` |
| 1005 | 量词没有可作用的对象（含连续量词、对锚点加量词） | `*a`、`a**`、`^*` |
| 1006 | 不支持的转义序列 | `\q`、结尾裸 `\` |
| 1007 | 多余的右括号 | `ab)` |
| 1008 | 重复次数过大（量词展开后指令数超过 100000） | `a{100001}` |

### 匹配错误（`BudgetExceeded`，含 `code`、`pattern`、`budget`、`start_pos` 属性）

| 错误码 | 含义 |
| --- | --- |
| 2001 | 匹配步数超出预算，已中止（规则在这段文本上超预算） |

## 目录结构

- `cleanre/parser.py` — 模式解析（AST + 字符级错误定位）
- `cleanre/compiler.py` — AST 编译为虚拟机指令（量词展开、空循环守卫）
- `cleanre/engine.py` — 回溯虚拟机、`Pattern`/`Match`、步数预算
- `cleanre/errors.py` — 错误类型与错误码
- `tests/` — `unittest` 测试：解析错误、语义、预算中止、样本验收、随机对拍

运行测试：`python3 -m unittest discover -s tests`
