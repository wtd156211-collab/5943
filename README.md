# 清洗引擎（内部批量文本清洗正则引擎）

内部有一个批量文本清洗工具在跑，清洗规则由同事手写正则。上个月出了两次事故：一次是某条规则碰到某段文本直接把进程挂死，跑了四十分钟没动静，最后只能杀进程；另一次是规则本身写错了，工具只回一句匹配失败，谁也不知道坏在第几个字符，写规则的人对着屏幕找了半天。现成那套不打算再用了，准备自己写一个。

这个项目要做的事情有三件。第一是不挂死：引擎带步数预算，超了立刻中止，并明确说明这条规则在这段文本上超预算，而不是一直转下去；中止之后引擎还得能接着用，不留脏状态，同一个进程里要连着跑几十万条。第二是能定位：模式写错时要说清是第几个字符、什么毛病，比如区间写反、括号没闭合、字符类没关。第三是可验证：清单覆盖到的语法要与标准库对得上，测试里跑带种子的随机对拍，两边给出的匹配区间和捕获结果必须一致；性能上常见的模式在那份语料上要在几秒内跑完。

仓库现在只有这份说明和 samples/ 下的三份材料，代码从零写：patterns.txt 是需要支持的语法清单（清单里没写的不做，不要自己扩），hang-case.txt 是上次挂死的那条规则，corpus.txt 是性能验收用的文本。实现只用标准库，测试用 unittest；除了测试里拿来对拍，实现本身不调用标准库正则。

文档方面，README 会随着实现补齐三件事：支持的语法、步数预算怎么算、错误码的含义。
